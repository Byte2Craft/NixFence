# Preparing a real Rocky/Alma/RHEL 9 target host

**Security-critical:** This beta uses privileged SSH commands without a tightly scoped host-side helper. Dedicated hosts and disposable VMs are recommended. Full production sudo hardening is a release blocker.

1. Enable `sshd`, `firewalld`, `systemd` and SELinux. Use a supported Rocky/Alma/RHEL 9 VM.
2. Create a dedicated `nixfence` SSH user with no password authentication. Provision and verify the public key generated by `scripts/bootstrap.py` (`secrets/id_ed25519.pub`).
3. Verify the SSH host key fingerprint out of band; add the exact corresponding host key to `secrets/known_hosts`. The key must match the address/port used when enrolling.
4. Permit the necessary non-interactive root operations. This beta uses `sudo -n` to execute: `firewall-cmd`, `getenforce`, `getsebool`, `setsebool`, `install`, `tee`, `chmod`, `systemd-run`, `systemctl`, `rm` and `/bin/sh`. **Allowing shell and file operations with sudo effectively grants root privilege.** Do not use this sudo scope on sensitive production hosts; the next release should replace it with a constrained root helper.
5. Verify `sudo -n firewall-cmd --state` and `sudo -n systemd-run --help` work under the dedicated SSH identity. `firewall-cmd --state` must report `running`.
6. Confirm the container can reach SSH on the target VM; host access must be restricted by networking and SSH authorized keys.
7. Test an allowed non-management port on a disposable VM. Confirm it and inspect runtime/permanent port state. Then test another port **without confirming**, disconnect SSH, and verify that the on-host timer reverts the port after the deadline.

## Linux container secret permissions

The image runs as UID/GID `10001`. On Linux, the host directory and secret files must permit the *container group* to read the private key and password but must not be world-readable:

```bash
sudo chgrp -R 10001 secrets
chmod 750 secrets
chmod 640 secrets/admin_password secrets/id_ed25519
chmod 644 secrets/known_hosts
```

Group access is intentional; keep GID 10001 restricted on the host. On Docker Desktop Windows/macOS, host bind-mount permission semantics differ; verify the app can read the files and protect the original files using platform ACLs. Never solve an access error with `chmod 777`.

## Limitations

Only one outstanding change per host. Removing the SSH management port is blocked if it matches the enrolled SSH TCP port; changes to other management-critical ports can still break connectivity. The rollback timer runs under systemd on the target host, not in Docker. A successful timer schedule is not a guarantee of recovery in every failure mode. Preserve independent console access while testing.
